1每个 Windows 11 应用都该抛弃 Electron，Discord 刚证明了原因
325 分 ｜ 300 评论 ｜ 已读原文 ｜ www.windowslatest.com
https://www.windowslatest.com/2026/11/06/every-windows-11-app-should-kill-electron-and-discord-just-showed-why-no-starting-screen-and-70-less-ram-even-with-two-accounts-signed-in/

Discord CTO Stanislav Vishnevskiy 发布的 15 秒对比视频显示，Rust 重写的客户端 Discord Phoenix 冷启动一秒内出窗口，而 Electron 版约五秒才进界面；新客户端在同时登录两个账号时占用 290.2MB 内存，比官方此前所说的 1GB 常驻低约 70%。Discord 没有选 Tauri，而是采用 Zed 团队的 GPUI（GPU 渲染、不用 HTML），移动端弃用 React Native，Web 端逻辑转向 WASM。文章据此主张 Windows 11 应用都该抛弃 Electron，但讨论指出它回避了 Electron 的核心卖点：一个团队、一套代码覆盖多平台。

社区讨论
  • 有评论指出 Electron 的价值一直是「一个团队做一份跨平台应用」，文章完全没有回应这个权衡；也有人反讽这就是「打包一个 Chrome 换来跨平台」。
  • 支持者认为 wxWidgets 开发体验差、Qt 不免费且无法复用 Web 代码，而 Electron 让既有 Web 代码库直接复用。
  • 一位法定失明用户表示，Electron 应用能按应用自定义界面缩放，这种可访问性让生活方便很多，而许多原生 GUI 框架多年只把它当待办事项。
  • 也有人提醒 Electron 2016 年发布时 IE 仍是主流，当年说得通，如今继续沿用这个理由已不充分。

4Claude Code 的「不再询问」在 1122 个公开 GitHub 文件中泄露密码
392 分 ｜ 269 评论 ｜ apiiro.com
https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again

Claude Code 的「Don't Ask Again」会把用户批准过的命令写进项目内的 .claude/settings.local.json，如果命令里直接含密码或密钥，这些凭据就被落盘。作者扫描公开 GitHub，发现 1122 个文件含有此类内容；放大风险的关键在于 Claude Code 只把该文件加入全局 gitignore，而不是仓库的 .gitignore，于是新克隆或第二台机器会照常把它提交。

社区讨论
  • 作者回应「是否真的公开」的质疑：1122 个文件都在公开仓库；私有仓库虽只对有权限者可见，但凭据会随克隆和 fork 扩散，仓库转公开就暴露。
  • 有评论认为标题夸大：单纯点「不再询问」并不会泄密，只有把设置文件提交、且批准的命令里直接写了密钥，才会暴露。
  • 作者追踪的 1105 个仓库中有 539 个，是 Claude 共同署名的提交改动了该文件，说明自动提交进一步放大了问题。
  • 也有人讨论相关质疑被自动标记的现象，认为可能是 LLM 或垃圾内容检测误伤，也有人坚持原帖属于 AI 生成内容。

12MaxxBench：DeepSWE 分数不错，但这是真的吗？
